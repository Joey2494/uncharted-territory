## 二.2 明确首个可玩目标和任务

### 玩家进入后能做什么

```
1. 看到一个 3D 房间，地上有蓝色武器，房间里有红色敌人
2. WASD 移动，走到武器上自动捡起
3. 鼠标左键近战攻击（捡到武器后才生效）
4. 敌人靠近会追击并造成伤害
5. 杀死敌人可能掉血药，走过去自动回血
6. 全部敌人清除后门打开，走进门进入下一房间
```

### 得到什么反馈

```
- 捡武器：HUD 从"无武器"变"已装备"，武器出现在手上
- 攻击：武器旋转挥砍动画
- 受击：角色闪红 0.1 秒 + 血条减少
- 杀敌：敌人消失 + 概率掉绿球
- 捡血药：血条回升
- 清敌：门从红色变绿/消失
- 死亡：弹出 Game Over + 探索到第几个房间
- 通关：弹出 You Win
```

### 一次尝试如何结束或重置

```
- 通关：清完 3 个房间 → "You Win" 界面 → 点"重新开始" → 重新随机生成
- 死亡：HP 归零 → "Game Over" 界面 → 点"重新开始" → 重新随机生成
- 每次重开房间模板随机选取，敌人重新生成，武器重新放置
```

### 本周优先验证的假设

```
「玩家能否在程序化生成的 3D 房间中完成 捡武器→打怪→开门→换房间 的完整循环？」

这是最不确定的部分，因为涉及：
- 3D 房间拼接是否穿模
- 武器拾取的 Area3D 检测是否可靠
- 敌人追击在房间边界是否卡墙
- 门的开关逻辑是否与清敌计数正确联动
```

# 决策记录：敌人检测范围

## 问题
敌人检测范围（detect_range）设多大合适？
试玩时发现玩家刚进房间还没捡到武器，敌人就冲过来打人了。

## 候选方案

| 方案 | 内容 | 预期效果 |
|------|------|----------|
| A | detect_range = 8（原始值） | 敌人老远就追，玩家来不及捡武器 |
| B | detect_range = 5 | 玩家有几秒空档走到武器位置 |
| C | detect_range = 8，但武器放在玩家出生点旁边 | 一出生就能捡到，不需要空档 |

## 测试条件
- 运行版本：main 分支 commit xxxxxxx
- 运行环境：Godot 4.7.2 编辑器，Windows 11
- 房间模板：room_template_01，房间大小 10x10
- 武器位置：距离 PlayerSpawnPoint 约 2 米
- 敌人位置：EnemySpawnPoint 距离玩家约 6 米

## 测试过程与观察

### 方案 A：detect_range = 8
- 玩家出生后 1 秒敌人就开始追
- 走到武器位置需要约 2 秒
- 被追上前只剩 0.5 秒，刚好捡到但立刻被打
- 截图：（方案A截图.png）

### 方案 B：detect_range = 5
- 玩家出生后敌人不动（距离 6 > 5）
- 走到武器位置捡起来（2 秒）
- 再朝敌人走 1 米进入检测范围，敌人才追
- 玩家有充分准备时间
- 截图：（方案B截图.png）

### 方案 C：武器放出生点旁边
- 一出生走 0.5 秒就捡到
- 但感觉"捡武器"这个动作太随意了，没有探索感
- 截图：（方案C截图.png）

## 最终取舍
采用方案 B：detect_range = 5

理由：
1. 给了玩家 2-3 秒安全窗口捡武器
2. 保留了"需要找武器"的探索感
3. 进入战斗后体验没有变化（敌人速度不变）
4. 修改量最小（改一个数值）

## 修改内容
文件：data/enemy_stats.gd
修改前：detect_range = 8
修改后：detect_range = 5
对应 commit：xxxxxxx

### 每人被提问时怎么回答

**俞吉依被问："你的 main.gd 怎么把所有模块连起来的？"**

```
"main.gd 在 _ready() 里做四件事：
 1. 调 generate(3) 拿到 3 个房间
 2. 把 player 放到第一个房间的 PlayerSpawnPoint
 3. 遍历每个房间的 EnemySpawnPoints 生成敌人，把 player 引用传给敌人
 4. 在第一个房间的 WeaponSpawnPoint 放武器拾取物
 然后连信号：hp_changed 连 HUD 的 update_hp_bar，
 enemy_died 连房间的 on_enemy_died 做清敌计数，
 item_picked 判断是 weapon 就调 equip_weapon，是 heal 就调 heal。"
```

**张宏伟被问："房间怎么拼接的？门怎么知道该开了？"**

```
"generate() 随机选 3 个模板 instantiate，沿 Z 轴每隔 12 米排一个。
 每个房间有 enemy_count 变量，敌人死亡时 on_enemy_died 把计数减 1，
 减到 0 就调 _open_door()，把门的碰撞关掉、Mesh 隐藏，
 玩家走进门的 Area3D 时发 door_entered 信号，main.gd 收到后
 把玩家传送到下一个房间的 PlayerSpawnPoint。"
```

**字远被问："敌人怎么找到玩家的？武器拾取怎么实现的？"**

```
"main.gd 生成敌人时把 player 的引用赋给 enemy.player_ref，
 敌人每帧在 _physics_process 里算跟 player 的距离，
 小于 detect_range 就用 (player.position - position).normalized() * speed
 算方向，move_and_slide() 移动过去。碰到玩家调 player.take_damage(1)。
 
 武器拾取是一个 Area3D，body_entered 检测到玩家后
 emit item_picked('weapon') 信号然后 queue_free() 自己消失。
 main.gd 收到信号后调 player.equip_weapon()。"
```

**汤志豪被问："HUD 为什么不会跟着画面动？血条怎么更新的？"**

```
"HUD 挂在 CanvasLayer 下面，CanvasLayer 是 Godot 的特殊节点，
 它不受 Camera3D 的变换影响，永远画在屏幕固定位置。
 血条是 ProgressBar，update_hp_bar(current, max) 被调用时
 设置 hp_bar.value = current，hp_bar.max_value = max。
 这个函数通过 player.hp_changed.connect(hud.update_hp_bar) 连接，
 玩家每次受伤或回血时自动触发。"
```
