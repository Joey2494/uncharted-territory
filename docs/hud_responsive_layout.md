# 游戏 HUD 的布局避让

主流程继续由 `scenes/ui/responsive_layout.gd` 计算 HUD 控件位置，生命、资源、教程、反馈、快捷栏、技能与 Boss 条的样式、数据和交互保持原有实现。

教程和 Boss 条定位时，会将可见的生命/资源面板、商城快捷入口、关卡目标及下方反馈/技能/快捷栏作为避让区域，并保留 16 个设计单位的间隔。优先保留正常宽度、在可用行中居中；紧凑窗口中教程避开商城入口。紧凑窗口中教程与 Boss 条同时出现、两者实际最小宽度允许时并排展示，为战斗保留更多垂直空间；其他情况下按可用区域放置，满足实际最小宽度并避开下方技能区。

计算使用实际容器最小尺寸和可见性；窗口大小、教程文案换行、商城显示状态、容器尺寸变化都会触发布局更新。库存刷新、关闭商城后也会重新避让。版本文字单独保留底部区域，避免进入技能或快捷栏；相机安全区域同步包含商城和版本文字。

游戏 HUD 不再提供常驻的“探索指引”和“Esc 暂停”按钮，也不为原导航栏保留布局占位。Esc 仍由 Main 的原有暂停逻辑处理。暂停菜单中的“操作指南”直接打开现有完整指南，关闭按钮或 Esc 均返回暂停菜单并恢复入口焦点，整个过程保持游戏暂停。设置中的“操作指南”仍返回设置页。设置与指南使用高于 HUD/商城、低于加载错误提示的显示层，教程和商城入口不会覆盖指南；阅读指南期间商城快捷键也不会打开背景面板。新手教程面板、商城快捷入口及其他 HUD 交互保留。

右上商城入口使用 64×64 圆形暗底、暗金边框及居中的 32×32 店铺 SVG 图标。正常、悬停、按下和禁用状态均保持圆形；原来的文字与金币图标替换为专属店铺图标，“商城 [P]”保留在悬停提示中，鼠标与 P 键打开原商城的行为不变。入口容器按按钮实际最小尺寸定位，不再保留矩形按钮的宽度。

第二关的任务提示采用最多 288×58 的两行石板任务栏：小号分类与一项相关进度在上，当前行动目标在下，不再同时列出房间名、导能和回环等多组状态。清敌进度读取 `RoomProgress` 的实际登记敌人数与剩余数；符文、分流、导能和出口读取地图/机关真实状态。`objective_presenter.gd` 只生成展示快照，不推进任务、发放奖励或操作门体。主线完成切换到下一行动，支线领奖后提示返回主路。

实际目标完成时，任务栏内显示 1.6 秒“目标完成”并短暂点亮左侧金色细线；普通任务切换显示 1.2 秒“任务更新”。反馈不扩展面板、不弹出模态窗口，每项真实完成状态在当前 HUD 中仅确认一次，回访不会重复庆祝。暂停冻结反馈计时；紧凑 Boss 战沿用隐藏任务栏的策略，隐藏期间保留完成反馈，在 Boss 条消失后显示。

从项目目录执行：

```text
godot --headless --path . --script res://tests/scenes/hud_compact_layout_tests.gd
```

测试使用独立角色与关卡档案。覆盖 1920×1080、1280×720、1180×720、1179×720、1024×768、800×600、720×720、640×360、480×800；1180/1179 额外验证宽窄布局临界点。第一关逐一检查八种教程展示文案以及 Boss 条显示/隐藏，第二关检查目标区与 Boss 条切换，并验证控件边界、相互重叠及实际相机安全区域。

交互检查使用真实 Esc 和 Enter 键及鼠标事件，覆盖两关暂停、直接查看指南、返回暂停、恢复焦点、设置内嵌指南和继续游戏；同时确认运行计时在暂停与指南中冻结，指南能覆盖并拦截背景入口。另检查商城、教程跳过、库存刷新及关闭商城后的布局。攻击、法术、闪避按钮和快捷栏还会实际触发战斗动作与药剂使用。图形模式添加 `-- --capture` 会将多尺寸及暂停/指南截图保存至本次验证输出目录；追加 `--navigation-only` 可只运行两关的暂停导航与截图检查。`-- --baseline` 只运行 720×720 的初始布局检查。

`tests/scenes/objective_hud_tests.gd` 用真实伤害、最近目标交互和物理出口覆盖清敌 → 导能 → 前厅 → Boss → 出口，以及校准 → 分流 → 开门 → 领奖，检查自动更新、部分进度、失败重置、完成反馈去重、暂停与隐藏后恢复。加 `-- --capture` 会采集圆形商城按钮状态、任务更新和多尺寸任务栏截图。
