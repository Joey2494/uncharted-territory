# 敌人图鉴

图鉴沿用角色图鉴的石质信息板、金色标题、独立数值卡和3D模型展示。首次进入战斗房、遇到未记录的敌人种类时，自动解锁并暂停战斗，显示名称、来历、数值、招式与应对要点。模型支持拖动旋转和滚轮缩放。

## 遭遇与解锁

| 关卡 | 收录敌人 |
| --- | --- |
| 第一关 | 骸骨巡守、遗迹守门者 |
| 第二关 | 丝蛛、母蛛、幼蛛、灾厄巨蝎 |
| 第三关 | 骨斧斥候、枯筋腐尸、长剑墓卫、双链执刑官、沙缚王 |
| 第四关 | 曦影、赤阳傀儡、白芒尖蓟、群鸦归巢、袍冠女巫、孢子守卫 |

共17种。相同种类跨房间、重复进房或新开局均不会重复弹出；一个房间出现多种未解锁敌人时，在同一次暂停中用“下一位”逐页查看。按“稍后查阅”可直接继续战斗，该批图鉴仍然全部解锁。

解锁基于实际战斗激活，不基于地图里是否存在模型；远处休眠的敌人和预加载女巫不会提前解锁。幼蛛和孢子守卫必须实际召唤出来才会记录。曦影假身不是独立物种，弹丸、毒池、特效和预览模型也不会触发收录。

主菜单和暂停菜单均有图鉴入口，游戏中按 **B** 打开，**Esc/B** 返回。未遇到的条目显示“未遭遇”和所属关卡，不展示真实名称、模型或招式。图鉴支持按关卡筛选。首次介绍关闭后恢复战斗；从暂停页打开则关闭后仍保持暂停，不会误恢复游戏。

## 保存

正式战役在首次遭遇时立即把稳定种类ID写入 `player_profile.cfg` 的 `profile.discovered_enemies`，无需击杀或成功通关。失败清空金币、道具时不清空图鉴。旧存档缺少该字段时从空图鉴开始；无效、重复ID会被过滤。保存失败时保留本会话记录并提供“重试保存”，后续成功保存档案也会一起保存图鉴。

独立试玩可浏览已保存记录，但新发现只保留在该试玩场景，不写入正式图鉴。

## 接口

- `data/enemy_codex.gd`：17个稳定ID、文字条目、基础数值、实际战斗对象识别和纯模型创建。第三、四关基础数值读取现有敌人配置；遭遇时以实际实例的最大生命、移动速度更新当前显示。幼蛛属于接触消耗型，不虚构独立血条。
- `CombatRoomEncounter.get_encounter_enemies()` 与第四关 `Combat.get_encounter_enemies()`：返回当前遭遇中的存活角色，只读，不改变封场或清场权限。
- `EnemyCodexController`：订阅实际 `battle_started`，处理动态召唤物、持久解锁、去重、待展示队列及暂停恢复；`record_actor(actor)` 是组员追加新遭遇时可调用的入口。
- `PlayerProfile.discover_enemy(id)`：写入图鉴并保存，重复ID不再次写盘；不消耗金币。新增敌人需先在目录中注册稳定ID和条目。
- `EnemyCodex.tscn` 与 `enemy_codex_screen.gd`：展示图鉴，布局支持横屏、方形和竖屏。预览只创建视觉模型，不实例化敌人AI、碰撞、攻击或掉落。
- `Main.RunState.CODEX`：图鉴占用模态期间冻结关卡与计时，拒绝其它暂停切换、购买和场景跳转；关闭恢复进入前的状态。

## 验证与试玩

Godot打开任一正式关卡并按F6开始。第一次进入有新敌人的战斗房会弹出图鉴；点“继续战斗”后可继续打，按B或暂停菜单“图鉴”可重新查阅。

```powershell
& 'D:/Godot/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe' --headless --path D:/uncharted-territory --script res://tests/enemy_codex_test.gd
```

专项使用隔离存档，覆盖四关真实进房、首领与召唤物、去重、锁定信息、读取时冻结、返回状态、存档重载、失败清空兼容、保存失败重试、试玩隔离以及17个模型的加载。截图在 `docs/enemy-codex-evidence/`。

旧战役流程测试不会主动关闭新图鉴，可在命令末尾添加 `-- --no-bestiary-popup` 只关闭测试进程的自动弹窗；该模式仍记录发现，不影响手动打开。图鉴专项不使用这个参数，实际验证自动弹出与继续流程。

原有背包与结算110项、第三关正式战役143项、第四关正式战役100项通过。第三关测试包含预期的加载失败恢复段；退出时仍可出现既有的ObjectDB清理提示。图鉴的横屏、720方形、720×1080竖屏，以及首次介绍、锁定条目、角色模型、主菜单和暂停入口均已进行实机截图检查。
