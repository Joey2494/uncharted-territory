# 复活卡与关卡奖励（2026-11-27）

场景中的卡牌是有厚度的 3D 双面卡，沿用其他道具的悬空、上下浮动和自动旋转。背包与商城仍使用平面图标。掉落改为稀疏分布，普通清场通常不额外产出道具；常规奖励最多一件，复杂解谜最多两件。随机补给为 20% 概率，每关最多一份。最新用户要求允许 G 邮轨左侧多件道具凑足500价值，因此该补给包是直接入包的专门例外，不改变其他房间掉落预算。

本次规则优先于旧文档中“失败保留此前永久资产”的说明。代码入口是 `data/item_catalog.gd`、`data/reward_balance.gd`、`scenes/items/item_inventory.gd` 和共用战役宿主 `Main.gd`。

## 复活卡

- 稳定道具 ID `8`，UI key `revival_card`，商城每张 500 金币；购买数量不受地图掉落额度限制。
- 购买和拾取后进入背包，可堆叠。快捷栏第五格显示持有数量；活着时不能消耗，背包会提示“倒下后选择原地复活”。
- 死亡动画结束后，如果持有复活卡，显示“使用复活卡”和“放弃复活”。选择使用扣一张，原位置满血恢复、清除蛛丝和沙咒迟缓，获得 3 秒无敌。能量、护盾、敌人剩余血量、机关、封场和背包进度保持当前状态，不重置战斗。
- 无卡或选择放弃才进行最终失败结算：携带金币和所有背包道具全部清空，包含此前通关带入和商城购买的道具。角色所有权、角色选择、通关记录保留。独立试玩仍与正式存档隔离。
- 通关时金币净变动与剩余道具（含未使用复活卡）一起原子保存，进入下一关载入。重复结算同一局不重复入账。
- 失败清空保存出错时，保留错误提示并在离开前重试，保存成功前不允许重新载入旧资产。待复活选择未完成时同样不能通过重开/跳场景绕过。

散落探索奖励在候选房间各抽一次：10% 少量金币、5% 手枪弹、5% 磁芯弹、80% 无物品。每关最多产生一份非空随机补给，抽空后不会因重访重新抽取。按第一至第四关分级为 3–6 金、3–6 发手枪弹或 2–5 发磁芯弹；最高折算价值不超过 8 金币，不包含符文或复活卡。候选点靠近机关操作区时留空，避免 E 键被补给抢占。固定教学药剂和战前补给保留。第四关 H 的清场金币补偿群鸦单体金币较低，使其含增援的总奖励高于 F。

因此当前是固定奖励为主、少量探索随机：清场奖励、解谜奖励、固定补给和复活卡的内容/位置/触发条件均为预设；只有上述候选探索点会随机判定。新开局重新抽取，同一局重访不刷新。邮轨两侧按商城价等额处理：左侧道具价值为2×10＋2×15＋10×20＋10×25＝500，右侧复活卡价值500。左侧24件道具一次直接入包，任何一种堆叠空间不足时整包不发放，允许稍后重试；不会在地面生成24个物品。

## 组员接口与测试

- `Catalog.REVIVAL_CARD`、`Profile.BAG_IDS`、`Inventory.get_count()`、`get_snapshot()` 已覆盖复活卡，商城/背包展示仍通过 `commerce_presenter.gd`。
- 动画继续监听 `Player.died`；不可逆地图停止监听 `Player.run_failed`。`Player.revived` 可挂接后续复活特效。不要在 `died` 里提前清空资产或终止正式关卡，否则会破坏复活。
- 复活入口由 `Main.allows_revival()` 授权，`Inventory.try_use_revival_card(host)` 一次扣卡后恢复角色。正常道具快捷键不能消耗复活卡。
- `Rewards.task(id)` 返回奖励包；`grant()` 用于可重试领取的交互奖励，`spawn_task()` 用于实体掉落。`scatter()` 用于低价值随机补给。`spawn()` 使用宿主一次性账本，不能把账本挂到会被临时销毁重建的机关模型。
- 在 Godot 打开 `scenes/dungeon/Level03Run.tscn` 或 `Level04Run.tscn` 按 F6。商城可购买复活卡，失败时选择使用或放弃；验证通关携带、失败清空与上述路径触发。
- 自动回归：`--headless --path D:/uncharted-territory --script res://tests/revival_rewards_test.gd`。测试使用独立档案，不会改动玩家正式存档。
