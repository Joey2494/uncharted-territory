# 当前整合版开发说明

## 开发基准与入口

使用 Godot 4.7.2，根目录 `project.godot` 指定 `Main.tscn` 为启动场景。本周整合基准提交到 `codex/week10-integrated-baseline` 供审查；合并后组员统一更新 `main`，再创建各自下周开发分支。下周安排和待复现问题见 `docs/week11-plan.md`。

测试版取消关卡锁，第一、第二、第三关对新旧存档均直接开放，确认角色后即可自由选关。正式入口分别为 `Main.tscn`、`scenes/dungeon/Level02Run.tscn`、`scenes/dungeon/Level03Run.tscn`；单独调试可直接运行对应场景。通关、已玩和最近游玩记录仍按真实行为保存；继续游戏回到最近实际游玩的关卡，新档没有游玩记录时不提供继续目标。

## 角色与操作

| 角色 | 初始状态 | 解锁金币 | 生命 / 角色护盾 / 能量 |
| --- | --- | ---: | --- |
| Knight 初始旅人 | 免费解锁 | 0 | 5 / 2 / 50 |
| Lan 游侠 | 锁定 | 100 | 5 / 1 / 50 |
| Iron 守卫 | 锁定 | 150 | 6 / 2 / 40 |
| Astra 术士 | 锁定 | 180 | 4 / 1 / 60 |

四名角色的 K 法术每次统一消耗 **5 点能量**，Astra 不再额外减耗；K 基础伤害 2、冷却 0.8 秒，成功释放后等待 1 秒再自然回能。

角色场景位于 `scenes/player/`，共享 `Player.tscn`。`character_catalog.gd` 负责角色配置，`character_ability.gd` 负责独特技能。金币及角色所有权由 `scripts/integration/player_profile.gd` 存入 `user://player_profile.cfg`。新玩家只有 Knight，开发者本机的金币、解锁与关卡存档不随源码共享。

Iron 使用原第一关 Boss 的 Barbarian 身体及独立圆盾、盔甲；第一关 Boss 使用 `BronzeGatekeeper.tscn` 的独立铜甲形象。Knight 的原始外形保留。菜单和战斗引用相同角色资源。

WASD / 方向键移动，J 使用当前武器，K 法术，L 角色技能，Space 闪避，E 拾取或操作机关，R 使用生命药剂，F 使用强化符文，G 使用守护，I 切换已拥有的手炮与近战，P 打开商城，Esc 暂停。I 不会自动获得手炮；手炮需要先获取并具有实际弹药。

第一关入口有实体药剂；强化符文教学等到玩家遇到支线房间内的真实符文后出现。教程控制器位于 `scenes/tutorial/`，音效连接位于 `scenes/audio/`。

## 三关与地图

`Main.gd` 管理三关的菜单、运行、暂停、死亡和胜利；`scripts/integration/run_bindings.gd` 连接玩家、经济、教程、音效和 HUD；`menu_navigation.gd` 负责关卡选择和设置。`campaign_progress.gd` 负责跨关进度。

第一关地图为 `scenes/dungeon/DungeonTest.tscn`。第二关地图在 `scenes/dungeon/level02/Level02.tscn`，通过 `Level02Campaign.tscn` 和 `campaign_level02.gd` 接入共享宿主。第二关 Boss 为灾厄巨蝎，击败后必须实际进入出口才结算。

第二关档案室是可选路线。C 区清敌并启动导能后，G 区可以操作能源。两枚能源可以在托架、手持与插槽之间回收转移。临时桥需要一枚能源，步道开关会展开无需持续供电的机械步道并接通断线。档案门要求两路接收器都供能且检修线接通。门完全开启后可在 H 领取一次强化符文，前台复位保留本局的领取记录。

第二关在 `level02.gd::_ready()` 按到达平台的局部偏移 `(0, 0.05, 2)` 初始化人物位置和零速度，当前实际出生位置为 `(0, 0.05, -3)`，避免导出场景内旧人物变换落在平台之外。本地 `week10-fixed.exe` 为本次修复后的 Windows 测试程序，包含嵌入资源；四名角色的菜单开局及直接开局均已在导出 EXE 内通过落地检查。

本次发现 `.godot/exported` 中继承场景的旧二进制缓存未随基础场景更新。后续整合导出前，先关闭正在进行的导出，将该生成缓存目录移到 `.godot` 内的备份位置，再重新导出，让继承场景重新生成；不需要清理源场景或美术资源。修复程序可用 `week10-fixed.exe --headless --fixed-fps 60 -- --week09-test test_level02_spawn` 运行开局回归，用 `test_level02_integration` 运行第二关流程回归。测试使用独立存档文件。

档案室与东侧/北侧通道切换采用 0.45 秒缓入缓出和 0.7 米退出缓冲，避免门槛往返抖动；进入 G 档案室后，相机固定呈现完整机关区域，保留与战斗区一致的道具和操作栏。目标卡持续显示手持、托架、桥和门锁的能源分布，数据直接来自机关的资源归属。场景只保留设施短标签，靠近后由底部提示显示完整名称、状态及当前 E 操作。提示卡按内容收缩，镜头使用固定预留区，反馈出现或消失不会推动取景。

第二关主线仍从 A 经 B、C、D、E 到 F。D 清敌后可开启回 B 的双向捷径，方便回访 G。布局和门的前置见 [第二关布局图](level02-layout.png)。B、C、D、E 封场后采用 44° 房间中心构图，清场后恢复跟随。取景覆盖真实房间；巨蝎靠墙时仅按实际轮廓扩大视距，不将巨蝎半径同时扩张至所有房间角落。二关 HUD 采用紧凑的顶部状态区和底部操作栏，目标卡与 Boss 条共用顶部中间位置。商城按钮由 ResponsiveLayout 统一排布，CommerceLayer 的 external_shortcut_layout 用于避免两处重复设置位置。

档案室机关采用短手柄与握球、贴地传动管线、低矮实体分隔台和带横肋的桥面。三块设备隔断始终不透明，不参与普通墙体遮挡淡化，边框显示其不可通行的占地；开关标为“步道开关”，交互提示说明展开返回路线和接通门锁的双重作用。手柄倾角与管线颜色反映检修状态，原两能源分配、桥台供电及回收规则不变；桥台边缘的模型与碰撞同高。

关闭的进度门保留至少 65% 不透明度，前景墙仍可淡出；门体视觉、升降和碰撞权限相互独立。相机读取遮挡体的 camera_fade_limit 元数据限制门的淡化程度，不能将关闭的门渲染成隐形墙。

第二关房间与通道使用天然岩壁、沉积岩地面、钟乳石、岩台与天然掩体；`stone_region.gd`、`stone_cover.gd` 通过 `cavern_geometry.gd` 更新可视外观。原有地图布局、碰撞、门洞、敌人和机关规则继续由团队实现负责，所有新增可视结构复用相机遮挡淡出。

`spider_habitat.gd` 加入蛛网、悬丝、蛛茧和巢穴，避让中央战斗区与门洞。结构与验证见 [天然蜘蛛洞窟](spider_cavern.md) 和 [蜘蛛栖息地陈设](spider_habitat.md)。

### 第三关潮汐工坊（临时第一关美术，已接入战役）

打开 `scenes/dungeon/level03/Level03Preview.tscn` 后按 F6 可独立试玩「潮汐回流工坊」。Tab 显示通路，Esc 暂停或重开。B 中央潮井控制水位。低水位开放西侧地沟，高水位开放东侧浮栈。把 C 的导体装到 D，东向为 F 充能，西向把储能送回 I。F 清场后可开启高架返程和维修井入口。I 泄压后开启 G，清除守卫后从 J 离开。H 是可选花园。

第三关通过 `Level03Campaign.tscn` 和 `campaign_level03.gd` 接入共享宿主，保留所选角色，支持暂停、商城、背包、设置、死亡重开和通关返回。目标卡常驻潮位、导体方向及蓄能状态。正式入口通过 Esc →「操作与路线」查阅低潮/高潮通路、充能回流和可选 H 路线，阅读期间游戏保持暂停，返回后仍停留在暂停菜单。潮位切换由水面、栈道和实体挡板表达。B 的复位装置需要再次确认，保留同局清场与已领奖励。

第三关十座交互台均具有与模型一致的实体基座，阻挡角色和碰撞层 1 的弹道。E 交互射线排除当前台体，但仍检查其他障碍，玩家必须绕台行走；连续主线回归也使用实际绕台路线。

第三关正式入口及独立预览直接复用第一关的 `scenes/dungeon/follow_camera.gd`：52° 俯角、50° 视野、最小视距 18，跟随速度 8、缩放速度 5，近/远裁剪 0.1/120。缓动跟随玩家与当前战斗房角色，按角色轮廓适配取景、处理前景墙淡出，与第一关使用同一实现。正式入口恢复第一关的 HUD 和安全取景布局配置。第三关独立固定镜头及 44°/36° 调整已撤下；不再按最大房间统一拉远。

本关接入 `addons/ziyuan_level03/` 中字远的 V3 模型和原有战斗数值：C 两名骨斧斥候；E 骨斧斥候与枯筋腐尸；F 枯筋腐尸与长剑墓卫；G 双链执刑官与首领沙缚王。共八名静态敌人，使用原有四个房间的封场、清场开门和镜头。`tide_enemy_encounter.gd` 将显式唤醒接口接到共享战斗房生命周期；其他房间未进入前保持休眠且不能受伤。

沙缚王提供真实 Boss 血条、三式预警和半血一次召唤两名骨斧斥候；援军不加入已封存的门锁名单，首领死亡时回收而不发回收奖励。敌人死亡按字远原数值生成可拾取金币，拾取后进入本局余额，仅成功离开出口才结算。沙咒命中后的 1.4 秒六成移速适配正式玩家，暂停冻结计时，翻滚距离不变。死亡或结算停止敌人并清理本关投射物、援军与临时特效。

必须完成 I 泄压、G 沙缚王和执刑官清场，等待出口门完全打开并实际进入 J 才结算；单独击败首领不能绕过机关或其他守卫。第三关结算不提供不存在的下一关。独立预览保留原有教学 HUD，正式入口使用统一 HUD；背景音乐暂复用第二关曲目。`tide_stone_visuals.gd` 复用第一关石砖、苔墙、石台，仅更换可视层；地图区域、路线、挡板、台体碰撞和机关权限保留张宏伟的实现，水面、栈道和状态灯保留辨识色。

## UI 与后续接入

界面以汤的 `scenes/ui/menu_theme.tres`、石纹与暗金风格为准。三关共用血量、能量、资源、快捷栏、冷却、暂停、商城、背包及设置界面。

角色选择页左侧使用统一四项属性卡，读取当前角色真实攻击、生命、护盾与常规移速，配以独立量程与属性条，已去除与旅人比较的差值文字、基准竖线和比较提示；底部保留两句人物与职业简介。角色机制以俞的 [角色设计](character-week9.md) 为准，包含 Knight 战斗补给、Lan 整备、Iron 近战击杀回盾和 Astra 清房回能；图标、技能说明与 HUD 保持同步。

商城新增「星蓝药剂」：ID 5、单价 15 金币、恢复 20 点能量，满蓝不消耗，可在背包或第六快捷栏使用。原五种物品 ID 和价格保持兼容。金币按字远的方案区分本局余额和永久钱包：本局可消费待结算金币，仅成功离开本关出口后将剩余金额入账一次；死亡、退出与重开不保留本局余额，跨关开始新局。永久钱包用于解锁角色。

`LevelObjective.tscn` 从真实地图读取当前目标和进度；窄窗口 Boss 战期间让位给 Boss 血条，战后恢复。第二关使用 `objective_presenter.gd` 适配地图与能源状态；第三关提供 `get_hud_objective()`，字段为 `id`、`title`、`category`、`progress`、`completed`（字符串数组）和可选 `resource_summary`。不要另建 UI 进度状态。无 Boss 地图还必须提供 `is_completion_ready()`，并由真实出口触发通关；结果摘要通过 `get_completion_snapshot()` 提供。

机关结算区分门升起中、门已开和奖励已领取；后续模块继续使用现有真实状态与信号。暂停、死亡或结算时不得独立继续推进资源、门动画或机关。

美术文件的来源及授权保留在各素材目录。保持现有模型和动画兼容节点路径，避免只替换外观后破坏骨骼动画、武器挂点或 Boss 接口。
