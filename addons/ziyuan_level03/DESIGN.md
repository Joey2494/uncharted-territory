# 基础近战与远程封路

## 骨斧斥候

定位：入门近战和追击牵制，先让玩家读懂短前摇与收招窗口。

外观：参考图一的三叉头饰与双手长柄斧。保留露出的肋骨、细长四肢、暗铁斧面和红色眼窝；体型矮于精英，武器轮廓比躯干更突出。

攻击：移速 2.9，靠近至 2.1 米后锁定朝向；0.52 秒扇形预警后挥斧，造成 1 点伤害。一次挥击只登记一次目标，伤害发生在挥击动作中段。

弱点：蓄力期能被控制或受击打断；离开正前方 100 度扇区，或从侧后方切入 0.9 秒收招期。没有额外护甲。

组合：与枯筋腐尸配对，由斥候逼迫玩家移动，给远程制造射线；首个教学组合只放两名斥候，避免一开始同时考验太多规则。

## 枯筋腐尸

定位：中距离压制与路径封锁；通过扇形弹道限制跑位，和第二关的单根蛛丝机制区分。

外观：按新参考图二替换为枯筋腐尸。细长的躯干和四肢、干枯筋腱、灰褐色残皮、凹陷眼窝和弯曲长指形成瘦削轮廓。没有外伸骨刺或头角。

攻击：攻击距离 10 米，0.68 秒三条射线预警后发射三团腐质弹；每团伤害 2，速度 10 米每秒，最远约 17 米，命中世界或玩家后消失。射出后不追踪玩家。

弱点：腐质弹能被石柱和墙体挡住；贴近后切侧面，利用 1.5 秒恢复期输出；普通受击和控制可打断蓄力。

组合：优先安排在开阔区的后排，给玩家留柱体和侧向通道；与长剑墓卫组合时，腐质弹逼走位、墓卫封直线，不把所有弹道集中到无路可躲的位置。

## 基础机制约束

两类敌人的伤害均走现有 take_direct_damage 或 take_damage 接口，尊重玩家翻滚无敌和守护状态。普通怪可被控制，敌人暂停时不推进攻击计时。预警本身不造成伤害。

# 精英敌人与明确弱点

## 长剑墓卫

定位：中前排精英，以直线爆发迫使玩家横向闪避；不是持剑版普通挥砍。

外观：参考图三的长剑、厚重单臂护甲和残破披布。灰铁肩甲与左护臂强调防守侧，右手细长武器强调刺击方向。

攻击：进入 7 米触发距离后，0.82 秒直线预警；沿锁定方向以 15.5 米每秒突进，最远 6.5 米。碰到玩家造成 3 点伤害，碰墙立即进入收招；不会穿过柱体。

弱点：非收招或受控时，正面直接伤害减半，至少 1 点；背侧正常受伤。突刺后 1.25 秒内承受双倍伤害。通用法术伤害绕过方向护甲，但仍受场景墙体查询约束。

组合：搭配一名枯筋腐尸；建议先引墓卫撞柱，再绕背反击。试炼场保留左右石柱，便于直接验证这个解法。

## 双链执刑官

定位：近中距离区域控制精英，处罚一直贴着外围绕圈的玩法。

外观：参考图四的铜锈肩甲、两条链鞭和腰部残布。链端随动作形成大轮廓，铜色装甲把它与长剑墓卫区分。

攻击：半径 4.8 米、270 度环形区域；第一段预警 0.9 秒，扫击伤害 4；第二段反向扫击前再预警 0.65 秒。每段独立锁定、独立登记一次伤害，不能在一个判定窗口重复扣血。

弱点：距其中心 0.95 米以内是近身安全口袋；也可完全撤出外圈或躲向未覆盖扇区。两段结束后有 1.3 秒恢复期，受到双倍伤害；硬控能打断普通精英出招。

组合：先与斥候搭配，让玩家学习“躲进内圈”；进阶可与枯筋腐尸搭配，但应限制远程数量，给内圈与外圈至少各留一条可行路径。

墓卫与执刑官的弱点在实际脚本里生效：方向护甲、撞墙收招、恢复期双倍伤害和扫链内圈都已加入自动检查，供组员在最终模型替换后继续回归。

# 沙缚王首领设计

按新参考图一重建为厚重绷带巨像：前倾宽肩、夸张巨臂、紫黑残躯和巨手、蓝色眼缝、封闭缠绕面罩、米色宽绷带、几何织纹和向后飘起的布尾。保留沙缚王的稳定 ID 和首领定位；伤害和场地控制均高于前四类敌人。

| 招式 | 预警与判定 | 伤害 | 应对 |

| 绷带撕扯 | 7 米 70 度扇形 动作中段命中 | 6 | 侧向翻滚或绕背 |

| 沙棺咒印 | 锁定玩家旧位置与两侧三个圆形区域 | 8 并减速 | 标记形成后离开圆圈 |

| 沙王重踏 | 5.3 米圆形 踏地动作中段生效 | 6 | 撤出范围后回身反击 |

基础前摇 0.95 秒、收招 1.2 秒。半血只触发一次狂暴：前摇缩为 80%，收招缩为 75%，并发送两名骨斧斥候的召唤请求。首领免疫硬控，仍接受减速，不会被普通攻击无限打断。

弱点是读预警后的反击窗口和咒印锁定旧位置。咒印不会追着移动中的玩家改坐标；命中被翻滚或守护阻挡时不附加减速。原型没有隐藏免伤或无提示的全场伤害。

## 与现有敌人的区别

第二关围绕蛛丝束缚、密集幼蛛和巨蝎尾部攻击。第三关改为不死战士体系：短扇区斧击、三路腐质弹、可撞墙的直线突刺、带近身安全口袋的正反扫链，以及按旧位置落下的沙咒。差别落实在移动轨迹、预警形状、碰撞、弱点和出招阶段，而非仅更换外观或颜色。

## 原型与正式整合的边界

试炼场沿用当前 Player 场景及 J 普攻、K 法术、Space 翻滚、R 药剂、I 切手炮。只在 prototype_player.gd 子类中将演示生命设为 24；每组补充 3 瓶药剂与 18 发弹药，不改共享角色数值，不写永久存档。

地图组可以把五个独立场景放入第三关房间。静态敌人按原有流程登记清场名单、封存后再激活。Boss 援军通过信号生成，不直接修改已经封存的名单；正式关建议视为召唤物，Boss 死亡后由房间宿主回收，避免援军变成额外门锁。实验室清场则检查所有已生成敌人。

最终玩家成长、角色护盾、地图宽度和补给量会改变难度。建议组内先确认第三关目标体力为 24 至 30 的量级，再微调伤害与同时在场数量；该建议不是已完成的正式成长系统。

## 外观替换范围

五张图片仅用于造型参考，没有作为贴图或成品模型装入运行包。当前模型为程序化低多边形原型，负责验证轮廓、武器和动作时机；正式布料、纹理、音效与专业骨骼动画仍可由美术及表现模块继续制作。

# 接口与交付验证

| 接口或信号 | 整合用途 |

| factory.create 稳定 ID | 创建任一敌人 支持显式传入玩家 |

| bind_target 与 set_encounter_active | 绑定玩家 房间进入时激活 停止时清预警及投射物 |

| take_damage 与 take_direct_damage | 通用伤害及方向护甲 尊重状态与终局 |

| hp_changed damage_received died | 连接血条 击杀反馈 与房间进度 |

| apply_control 与 apply_slow | 普通怪打断 首领硬控免疫与减速 |

| reward_requested | 发送一次奖励请求 由现有背包接入待结算金币 |

| summon_requested status_requested | 请求援军或通知减速 由宿主适配 |

| attack_telegraphed attack_resolved | 给 UI 音效提供时机 不反向控制伤害 |

完整接口签名、生成示例、碰撞层、资源依赖和房间清场注意事项见合并包 INTEGRATION.md。敌人保持 CharacterBody3D，碰撞层采用世界 1、玩家 2、敌人 4，加入 camera_targets 并提供取景元数据。

敌人模块放在 addons/ziyuan_level03；不覆盖 Main.gd、共享 Player.gd、project.godot 或现有地图文件。Visuals 的 pose 入口可适配最终模型。奖励请求不直接写钱包，仍由主机按实际出口成功结算；奖励源 ID 应带本局唯一标识。

## 验证与使用

已通过 45 项原型检查，涵盖伤害阶梯、休眠与接口、实际近远程命中、翻滚、护甲、弱点、柱体拦截、扫链内圈、沙咒躲避与减速、半血召唤、死亡奖励幂等、暂停、旧回调拦截及失败后原组重试。

Godot 4.7.2 可直接 F6 运行 addons/ziyuan_level03/Prototype.tscn。数字 1 至 5 切换组合；上方按钮打开图鉴或重试；Esc 暂停。Windows 导出包提供无需安装 Godot 的启动程序。测试脚本通过定点移动隔离路程，不代表人工连续通关或最终难度验收。
